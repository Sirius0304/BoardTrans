## 二、阻断性问题（必须修复）

### P0-1　LICENSE 与 THIRD-PARTY-NOTICES.md 未提交到 git

**现象**

```
$ git status --short
 M README.md
?? LICENSE                  ← 未跟踪
?? THIRD-PARTY-NOTICES.md   ← 未跟踪
```

**影响**

README 里已经写了 `详见 [LICENSE](LICENSE)`，指向一个**远端仓库不存在的文件**。
在 GitHub / Gitee 的项目页面上：

- 许可证标识会显示为 **"未声明许可证"**；
- 法律上等同于**保留所有权利**（All rights reserved）——他人即使拿到源码，
  也没有合法授权去使用、修改或分发；
- 链接点击后会 404。

这直接违背"开源"的前提：**代码公开 ≠ 授权他人使用**。

**修复**

```bash
git add LICENSE THIRD-PARTY-NOTICES.md README.md
git commit -m "添加 MIT 许可证与第三方组件声明"
git push origin main
```

**验证**：推送后仓库主页应出现 "MIT" 许可证标识；点击 LICENSE 能正常打开。

## 三、需要关注的问题（合规建议）

### P1-1　模型是 CC-BY 4.0，署名义务需随分发传递

经核查 `models/packages/zh_en/README.md`：

> The original OPUS model from which this packaged model is derived is
> licensed **CC-BY 4.0**
> Authors: Jörg Tiedemann and Santhosh Thottingal

**要点**：

- 翻译模型**不是 MIT**，CC-BY 4.0 **允许商用与再分发，但必须署名原作者**；
- `models/` 目录已在 `.gitignore` 中排除，**仓库本身不含模型**——
  因此**克隆仓库者**不触发署名义务（他们需要自行下载）；
- 但**再分发模型的行为**（随 exe 附带 models 目录、或单独分享模型包）**触发**署名义务。

**现状**：模型包内自带署名文件 `README.md`，且根目录已建
`THIRD-PARTY-NOTICES.md` 记录完整署名。**已具备合规基础**。

**建议**：发布 Release 附带模型时，在发布说明（Release Notes）中同时给出
OPUS-MT 署名与 CC-BY 4.0 链接，形成双重保障。

### P1-2　单独分发 exe 时，第三方声明未随行

`瞬译.exe` 内嵌了 CTranslate2、SentencePiece、keyboard、pyperclip、
Pillow、pystray、PyInstaller 共 7 个第三方组件。

若主人只把 `瞬译.exe` 发给他人（不含项目其他文件），对方拿不到任何许可声明。
其中 **pystray 为 LGPLv3**——该许可证要求使用者能够替换库版本，
分发时提供来源声明是稳妥做法。

**建议**：分发时把 `LICENSE` 与 `THIRD-PARTY-NOTICES.md` 一并附上；
或把它们放入随 exe 分发的压缩包中。

### P1-3　仓库存在 82 MB 悬空对象（不影响合规，影响健康度）

审计发现 `.git` 目录 118 MB，而实际源码仅 1.3 MB。定位结果：

```
悬空对象合计：82.1 MB
  · 29 MB blob   —— 疑似模型文件
  ·  7 MB blob   —— MZ 开头，Windows 可执行文件
  ·  4 MB blob   —— PYZ 开头，PyInstaller 打包归档
  · 另有 11 个小对象 + 1 个悬空提交（2026-10-01，疑似 amend 前的版本）
```

**这些对象不可达**（`git fsck` 报 dangling），因此：

- **不构成许可证风险**：clone / fetch 只传输可达对象，他人拿不到这些内容；
- 但**本地仓库臃肿**，且这些残留包含打包产物（二进制）。

**修复**（可选，安全操作）：

```bash
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

预计可回收约 80 MB。
