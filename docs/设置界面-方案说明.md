# 设置界面 · 方案说明

> 目标：在托盘右键菜单里加一个「设置」，打开图形窗口完成——模型下载管理、翻译档位、快捷键配置，保存后立即生效并持久化，且**不改动任何现有功能**。

---

## 一、GUI 库选型：tkinter + ttk（Python 标准库）

| 候选 | exe 体积影响 | 打包稳定性 | 结论 |
|---|---|---|---|
| **tkinter + ttk** | **+约 3 MB**（只多带 tcl/tk 运行时） | PyInstaller 内置 hook，自动收集 tcl/tk，最稳 | ✅ **采用** |
| PyQt5 / PySide6 | +80~130 MB | 需要额外 hook，易漏 DLL | ❌ 体积翻 2~3 倍；PyQt 还有 GPL/商业双授权问题 |
| wxPython | +40 MB 起 | 打包后常见 DLL 缺失 | ❌ |
| CustomTkinter 等美化库 | 小 | 依赖 Pillow，但只是"更好看" | ➖ 收益有限，不加 |

选 tkinter 的核心理由：**零第三方依赖、打包体积增加最小、PyInstaller 支持最成熟**。
界面观感用 `ttk` 主题 + 分区卡片式布局 + Windows 11 高 DPI 适配，足够清晰不糊。

> ⚠️ **前提条件**：所用 Python 必须带 tkinter。Python 官网安装包默认自带，
> 但本机原先的托管 Python 是精简版（无 tkinter），已改用系统 Python 3.13.15 重建项目环境。
> 程序对"tkinter 不可用"这种情况做了兜底：点「设置」会弹出说明而不是崩溃。

## 二、线程模型（这一步决定了"不破坏现有功能"）

**现状**：主线程被 pystray 的 `icon.run()` 占着（托盘消息循环）。
**约束**：tkinter 的 `Tk` 实例只能由创建它的线程使用，跨线程操作 GUI 会崩。

**方案：托盘主线程原封不动，设置窗口独占一个常驻子线程**

```
主线程（不变）      pystray icon.run()  ── 托盘图标、菜单、所有快捷开关
                          │ 队列（queue.Queue，线程安全）
                          ▼
子线程（新增·常驻）  tkinter Tk + mainloop ── 设置窗口
```

要点：
1. 托盘菜单回调**绝不直接碰 Tk 对象**，只往队列放一个 `"show"`；
   窗口线程用 `root.after(120ms)` 轮询队列，取出后再 `deiconify()`。
2. 窗口线程常驻，首次创建后 `withdraw()` 隐藏。点「设置」= 把已有窗口显示出来，
   **天然实现"不重复创建"**，且打开是秒开。
3. 关闭窗口 = `withdraw()` 隐藏（不销毁），软件继续在托盘运行。
4. 这样**托盘、全局热键、取词翻译回写三条链路一行都不用改**。

## 四、设置项 ↔ 配置文件映射

| 界面控件 | `config.json` 键 | 取值 | 生效方式 |
|---|---|---|---|
| 快捷键录制框 | `hotkey` | `alt+j` 等"修饰键+主键" | 保存时先试注册，成功才落盘并重注册 |
| 「高速度 / 高质量」单选 | `quality` | `fast` / `quality` | 保存后 `service.reload_config()`，下次翻译即用新档位 |
| 模型管理卡片 | （无对应配置项） | 直接反映磁盘状态 | 下载/删除后刷新卡片 |
| 托盘菜单 | 复用上面两个键 + `enabled` | — | 托盘与窗口读的是**同一份 config**，天然一致 |

保存流程：`config.update(...)`（写临时文件 → fsync → 原子替换）→ `service.reload_config()`。
取消/关窗有未保存改动时二次确认；「恢复默认设置」二次确认后回填界面（仍需点保存才落盘）。

## 五、快捷键录制与冲突检测

**录制**：录制框绑定 `<KeyPress>`，只记录修饰键状态，按下主键时组装成 `ctrl+alt+j` 这种形式：

- 只按修饰键（Ctrl/Alt/Shift/Win）→ 不算完成，提示"继续按主键"
- 无任何修饰键的纯单键（如 `J`）→ **拒绝**，提示"请至少包含一个 Ctrl/Alt/Shift/Win"
- `Esc` → 取消本次录制；`Backspace` → 清除

**冲突检测与生效（关键）**：**先试注册，成功才改配置**，顺序保证绝不会出现"新键没设上、旧键也丢了"：

```
1. 试注册新键   keyboard.add_hotkey(new_key, 空函数, suppress=True)
   ├─ 失败 → 弹提示"该快捷键已被占用或被禁用"，配置文件不动，旧键继续有效
   └─ 成功 → remove_hotkey 试注册的 handler，继续
2. service.set_hotkey(new_key)
   ├─ 注销旧键 → 注册新键
   ├─ 注册失败 → 自动回滚注册旧键 + 提示
   └─ 注册成功 → config.update(hotkey=new_key) 落盘
3. 立即生效，无需重启
```

## 六、如何保证不破坏现有功能

| 现有能力 | 保障措施 |
|---|---|
| 快捷键取词 / 翻译 / 回写 | 完全不改 `capture.py` / `engine.py` / `injector.py`；`service.py` 只**新增** `set_hotkey()` |
| 托盘常驻与快捷开关 | `tray.py` 只**新增**一个「设置」菜单项，其余菜单项与回调零改动 |
| 全局钩子稳定 | 热键重注册走 `register_hotkey()` 的原有 try/except 兜底；失败自动回滚旧键 |
| 状态持久化 | 复用原有原子写（写临时文件 → fsync → `os.replace`），断电/强杀不丢 |
| 托盘与窗口一致性 | 两处共用 `config.load()`；窗口显示期间每 500 ms 比对一次配置，**未被编辑时就自动同步**；窗口有未保存改动时显示醒目提示条并标注"当前生效值" |
| 托盘快速切换期间窗口显示 | 同上机制：托盘改了档位 → 窗口未处于编辑态 → 自动刷新为新值，不会出现"显示 A 实际 B" |
| 首次运行无模型 | 翻译时检测到缺模型 → 弹通知"模型未下载，请打开托盘菜单 → 设置 → 下载模型"；设置窗口内模型卡片直接显示「未下载」+ 下载按钮 |
| 完全离线 | 新增代码只在用户**主动点「下载」**时联网，翻译路径不引入任何网络调用 |
| 单文件 exe | 打包命令追加 tkinter 相关的 tcl/tk 数据收集（PyInstaller 自动处理，实测体积 +约 3 MB） |
