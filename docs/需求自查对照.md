## 一、关键设计一览

| 设计点 | 做法与理由 |
|---|---|
| **取词** | 混合方案：有选中内容就用选中的；没有就自动选中光标以前的整行。兼顾精确与流畅 |
| **翻译引擎** | 直接加载 `.argosmodel` 里的 CTranslate2 模型，**不依赖 argostranslate 库**（它会把 PyTorch 拉进来，体积 2 GB+），运行时依赖降到 60 MB |
| **两档质量** | 同一模型、不同解码策略：高速档贪心解码（beam=1），高质量档束搜索（beam=8）+ 长度惩罚。实测耗时 26 ms vs 54 ms |
| **中→日** | 官方无直连模型，采用 `zh→en→ja` 中转；并对日文方向设了 `beam≥3` 下限（实测 beam=1 会严重错译） |
| **回写** | 默认剪贴板粘贴 + **粘贴后还原原剪贴板**；可选 `type` 模式完全不碰剪贴板 |
| **状态记忆** | 配置"写临时文件 → fsync → 原子替换"，强杀/断电都不会损坏 |
| **性能坑** | 已修复：路径探测原本每次写删探针文件（开启实时防护的 Windows 上单次 110 ms），改为缓存一次，中→日耗时 147 ms → 36 ms |
| **路径要求** | 数据目录必须是纯 ASCII 路径（sentencepiece 无法打开中文路径），程序自动保证并支持 `BOARDTRANS_DATA_DIR` 覆盖 |
| **稳定性** | 热键回调只入队（微秒返回），实活在工作线程；全流程异常兜底，绝不崩钩子 |
| **下载健壮性** | 写文件前兜底建父目录；目录迁移逐项搬、绝不删目标；HTTPS 走 certifi 的 CA 包（2026-10-11 修） |
| **设置界面** | **tkinter + ttk**，零第三方依赖、exe 只增 2.9 MB（PyQt 会增 80~130 MB） |
| **设置界面线程模型** | 托盘主线程不动（pystray 消息循环），设置窗口独占常驻子线程；托盘只往线程安全队列放指令，避免跨线程操作 GUI |
| **设置窗口去重** | 窗口创建后常驻不销毁，点「设置」只是显示出来 → 天然"已打开则置前、不重复创建"，且秒开 |
| **托盘与窗口一致性** | 两处共用同一份 `config.json`；窗口未被编辑时每 120 ms 比对一次配置自动同步，不会出现"显示 A 实际 B" |
| **快捷键冲突** | 保存前用 Win32 `RegisterHotKey` 探测占用；失败则**保留原快捷键**（先探测、再切换、失败回滚），绝不出现"新键没设上、旧键也丢了" |
| **模型下载** | 后台线程 + 进度回调 + 可取消；每写一块即落盘，取消后保留已下部分，下次断点续传 |
| **删除模型** | 二次确认（明确提示影响与释放空间）→ 先卸载引擎释放文件占用 → 删除；文件被占用时给可读提示而不是崩溃 |
