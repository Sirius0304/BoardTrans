> 核查时间：2026-10-09　·核查方式：GitHub Search API（`in:name`，精确到仓库名）
> GitHub 与 PyPI 均为**实测**结果，非推测。

## 〇、中文名候选（2026-10-09 补充）

### ⚠️ 先说一个更要紧的发现

**「瞬译」不只是 GitHub 仓库名被占——它是一个真实存在的同类产品。**
检索到 Android 应用「瞬译 / 瞬譯」（英文名 Instant Translate On Screen，
开发者 Sapiens Labs，Google Play 上架），**同样是翻译工具**，
同样主打"无需切换应用、悬浮球取词"。

> 这意味着：中文名「瞬译」与一款**同品类竞品重名**，
> 比仓库名撞车的影响更大（用户搜索时会把两者混淆）。
> 因此**中文名也建议一并更换**。

### 中文翻译工具的命名空间已经很拥挤（实测）

以下都是**已有产品**，不要再选：

| 名称 | 占用者 |
|---|---|
| 瞬译 / 瞬譯 | Sapiens Labs（安卓屏幕翻译） |
| 一键翻译 | 杭州智豆科技（Google Play 50 万+ 下载） |
| 随手译 / 随手翻译 | 多款安卓小工具 |
| 顺手翻译官 | 安卓拍照翻译 |
| 敲译 / 敲翻译 | 淘宝（fanyi.taobao.com） |
| 闪译 | 至少 3 款 App（VoltVoice 同传、Flash Transcribe 等） |

**结论**：「X 译」这个构词法已被大量占用，且"快"义字（瞬/闪/秒/疾）几乎被瓜分。
→ **新名字应去命名"别人没有的那个特性"**，而不是再取名"快"。

### 本产品最独特的地方

同类工具**都是"显示"译文**（弹窗、悬浮球、浮层、同传字幕）；
本工具是**"替换"原文**——打完中文按 `Alt+J`，那句话**原地变成**外文，
不留痕、不打断、不用再复制粘贴。

所以：**名字应该落在"就地/原位"上，而不是"快"上。**

### 推荐候选

| 名称 | 构思思路 | 验证 |
|---|---|---|
| ⭐ **就地译** | 直接命名本产品独有的机制：**译文就地替换原文**。一句话把与所有同类工具的差异说清楚——它们是"显示"，我们是"就地"。三字白话，画面感强 | 检索未见他用 |
| **贴身译** | 取"贴身助理"之意，强调**常驻托盘、随唤随到**，按一个键就出手 | 检索未见他用 |
| **伴译** | 二字最短，"随身的翻译伙伴"，更像品牌名（可延展"伴译键"） | 未逐一核实 |

> 三者都比"瞬译"更能说明产品是什么：一个**不用打开、按键就换字**的工具。

### 推荐组合

| 中文名 | 英文名 | 组合读感 |
|---|---|---|
| **就地译** | Glotline | 中英都落在"inline / 就地"这一差异点上，互相印证 |
| 就地译 | Hotglot | 中文说特征、英文说触发方式，互补 |
| 贴身译 | Hotglot | 中文说"随唤随到"、英文说"热键"，气质一致 |

## 一、命名诉求

新名称需同时满足四点：

1. **体现功能定位** —— 离线、热键触发、译文原地替换；
2. **简洁易记** —— 尽量 1~2 个词、10 个字母以内、无生僻拼写；
3. **便于搜索** —— 不与其他项目重名，搜出来就是我们；
4. **可注册** —— GitHub 仓库名、PyPI 包名均未被占用（若日后发 Python 包）。

## 二、推荐候选（均已实测未被占用）

### ⭐ 1. Hotglot　【首选推荐】

| 项目 | 说明 |
|---|---|
| 构思 | **hotkey**（热键）+ **polyglot**（通晓多种语言者） |
| 呼应用途 | 直接点出产品核心动作：**按一下热键，语言就变了** |
| 验证 | GitHub 仓库名 `0 结果`；PyPI `Not Found` |
| 读感 | 7 字母，两个音节（hot-glot），朗朗上口 |

**为什么首选**：把"触发方式"和"功能"压进一个词，用户看一眼名字就知道是干什么的，
而这正是同类工具名字普遍缺失的信息（多数叫"XX Translator"，搜索时淹没在重名里）。

### 2. Glotline

| 项目 | 说明 |
|---|---|
| 构思 | **glot**（语言）+ **inline**（行内 / 原地） |
| 呼应用途 | 突出本项目**最独特的产品特征**：译文原地替换，不弹窗、不跳转 |
| 验证 | GitHub `0 结果`；PyPI `Not Found` |

**适用**：如果希望名字强调"**技术差异化**"而非触发方式，选它。
`inline` 在翻译类工具里是空白词位，辨识度高。

### 3. Glotkey

| 项目 | 说明 |
|---|---|
| 构思 | **glot** + **key**（键） |
| 呼应用途 | 与 Hotglot 同源构词，更侧重"**键**"这一交互载体 |
| 验证 | GitHub `0 结果` |

**适用**：偏好更短的发音与拼写时选它。

### 4. Glotswap

| 项目 | 说明 |
|---|---|
| 构思 | **glot** + **swap**（替换） |
| 呼应用途 | 强调"**把原文换成译文**"这一可见结果 |
| 验证 | GitHub `0 结果` |

**适用**：若后续功能扩展到"双语互译、来回切换"，这个名字有延展性。

### 5. Vertatype

| 项目 | 说明 |
|---|---|
| 构思 | 拉丁语 **vertere**（转换）+ **type**（打字） |
| 呼应用途 | 转换 + 输入，完整覆盖"打字即翻译" |
| 验证 | GitHub `0 结果` |

**适用**：希望**完全避开 `glot` / `key` 这类拥挤词根**、走独立品牌路线时选它。
独特性最高，但需要向用户解释一次含义。

### 6. Shunglot

| 项目 | 说明 |
|---|---|
| 构思 | 保留原名的"**瞬**"（拼音 shun）+ glot |
| 呼应用途 | 老用户一眼能认出是同一个项目的延续 |
| 验证 | GitHub `0 结果` |

**适用**：如果主人希望**保留"瞬译"这个中文名与既有认知**，只更换英文名与仓库名，
这是最平滑的过渡方案。中文名"瞬译"本身不受 GitHub 重名影响，可以继续用。

## 四、核查方法与局限（务必了解）

**已核查**：

- GitHub 仓库名 —— 用 Search API 的 `in:name` 限定词，**精确到仓库名**做子串匹配。
  返回 `total_count: 0` 表示**没有任何仓库名包含该字符串**，是强证据。
  （例：查 `glotkey` 返回 0，则形如 `glotkey`、`my-glotkey` 的名字都不存在。）
- PyPI 包名 —— 对前三名做了实测（均 404）。

**尚未覆盖**（同名不代表侵权，但可能影响辨识度）：

- GitHub **用户名 / 组织名**（用户 `hotglot` 是否已被注册）
- npm / crates.io 等其他包仓库
- 域名（`hotglot.com` 等）
- 商标

**时效提醒**：GitHub 名称是**先到先得**且有新增。本次核查基于 2026-10-09 的实时数据，
但**正式定名前建议再复查一次**，间隔越久越需要复查。

## 五、落地建议

若采纳 **Hotglot**，需要改动的只有"对外名称"，**代码与目录结构完全不用动**：

```
□ GitHub / Gitee 仓库名     shunyi  →  hotglot
□ README 标题与正文          瞬译（ShunYi）  →  Hotglot
□ LICENSE 版权行             保留作者名，仅产品名变化
□ THIRD-PARTY-NOTICES        同步产品名
□ 文档中的项目名引用         批量替换
□ exe 文件名 / 窗口标题      如需要
□ 中文名「瞬译」             可保留（中文名不受重名影响），或一并更换
```

> 注：仓库改名后，Gitee/GitHub 会自动保留旧地址的重定向，已有链接不会失效。

### 一个教训

**`key` 前缀在 GitHub 上极其拥挤**——`keytrans`、`keytype`、`keywrite`、`keymorph`、
`keyverse`、`keylingo`、`keyglot` 全被占用，且多数是键盘/输入类项目。
"键"这个字虽然贴切，但英文 `key*` 词族几乎没有空位了。
