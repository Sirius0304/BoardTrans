# 瞬译（ShunYi）· 打字即翻译

> 在任意软件里用中文打字，按一下 `Alt + J`，刚才那句话**原地变成英文或日文**。
> 完全离线，不联网翻译，不需要 API Key。
> 托盘右键「设置…」可打开**图形化设置界面**，管理模型、切换档位、录制快捷键。

| 项目 | 说明 |
|---|---|
| 平台 | Windows 10 / 11（64 位） |
| 翻译方向 | 中文 → 英文、中文 → 日文 |
| 引擎 | CTranslate2 + OPUS-MT 神经网络模型（本地推理） |
| 模型体积 | 186 MB（中→英 71 MB + 英→日 115 MB），**只需下载一次** |
| 实测速度 | 中→英 26 ms/句（高速档）/ 54 ms（高质量档） |
| 设置界面 | tkinter（Python 标准库），仅让 exe 增加约 2.9 MB |
| 形式 | 托盘常驻，可打包成单个 exe（**34.1 MB**，Windows 显示值），双击即用 |

> ⚠️ **环境要求**：设置界面用到 Python 自带的 **tkinter**。
> Python 官网安装包默认自带；若用精简版/绿色版 Python 会缺这个库，
> 此时程序不会崩，点「设置」会弹提示告诉你如何解决（翻译功能不受影响）。

## 🚀 三步开始

| 步骤 | 操作 |
|---|---|
| **① 准备环境** | 双击 `0-准备环境.bat`（本机已装好，可跳过） |
| **② 开始使用** | 双击 `2-托盘版.bat`（首次会自动提示下载模型） |
| **③ 打包成 exe** | 双击 `3-打包exe.bat` → 得到 `dist\瞬译.exe` |

**用法**：在记事本/微信/浏览器地址栏里打中文 → 按 `Alt + J` → 原地变译文。
**设置**：右键托盘图标 →「设置…」→ 管理翻译模型 / 翻译档位 / 快捷键。

> 出问题先双击 `0-自检.bat`，它会逐项体检并告诉你怎么修。

## 🔑 关键设计一览

| 设计点 | 做法与理由 |
|---|---|
| **取词** | 混合方案：有选中内容就用选中的；没有就自动选中光标以前的整行。兼顾精确与流畅 |
| **翻译引擎** | 直接加载 `.argosmodel` 里的 CTranslate2 模型，**不依赖 argostranslate 库**（它会把 PyTorch 拉进来，体积 2 GB+），运行时依赖降到 60 MB |
| **两档质量** | 同一模型、不同解码策略：高速档贪心解码（beam=1），高质量档束搜索（beam=8）+ 长度惩罚。实测耗时 26 ms vs 54 ms |
| **中→日** | 官方无直连模型，采用 `zh→en→ja` 中转；并对日文方向设了 `beam≥3` 下限（实测 beam=1 会严重错译） |
| **回写** | 默认剪贴板粘贴 + **粘贴后还原原剪贴板**；可选 `type` 模式完全不碰剪贴板 |
| **状态记忆** | 配置"写临时文件 → fsync → 原子替换"，强杀/断电都不会损坏 |
| **性能坑** | 已修复：路径探测原本每次写删探针文件（开启实时防护的 Windows 上单次 110 ms），改为缓存一次，中→日耗时 147 ms → 36 ms |
| **路径要求** | 数据目录必须是纯 ASCII 路径（sentencepiece 无法打开中文路径），程序自动保证并支持 `SHUNYI_DATA_DIR` 覆盖 |
| **稳定性** | 热键回调只入队（微秒返回），实活在工作线程；全流程异常兜底，绝不崩钩子 |
| **设置界面（新增）** | **tkinter + ttk**，零第三方依赖、exe 只增 2.9 MB（PyQt 会增 80~130 MB） |
| **设置界面线程模型** | 托盘主线程不动（pystray 消息循环），设置窗口独占常驻子线程；托盘只往线程安全队列放指令，避免跨线程操作 GUI |
| **设置窗口去重** | 窗口创建后常驻不销毁，点「设置」只是显示出来 → 天然"已打开则置前、不重复创建"，且秒开 |
| **托盘与窗口一致性** | 两处共用同一份 `config.json`；窗口未被编辑时每 120 ms 比对一次配置自动同步，不会出现"显示 A 实际 B" |
| **快捷键冲突** | 保存前用 Win32 `RegisterHotKey` 探测占用；失败则**保留原快捷键**（先探测、再切换、失败回滚），绝不出现"新键没设上、旧键也丢了" |
| **模型下载** | 后台线程 + 进度回调 + 可取消；每写一块即落盘，取消后保留已下部分，下次断点续传 |
| **删除模型** | 二次确认（明确提示影响与释放空间）→ 先卸载引擎释放文件占用 → 删除；文件被占用时给可读提示而不是崩溃 |

## ⚠️ 已知限制

1. **中→日质量弱于中→英**（经英文中转所致），日常对话够用，正式文本建议核对。
2. **管理员权限窗口**需要本程序也以管理员运行才能取词（Windows UIPI 安全机制，非程序缺陷）。
3. `paste` 模式下译文会进 Windows 剪贴板历史（Win+V），改用 `type` 模式可避免。
4. 自动取词的范围是"光标所在行"，一句话跨多行时建议先手动选中。
5. **设置界面需要 Python 带 tkinter**：官方安装包默认自带；精简版 Python 会缺，
   此时点「设置」会弹提示说明如何解决（翻译功能完全不受影响）。
6. **Win 键组合无法在窗口内录制**（会被系统优先占用），需要在 `config.json` 里手工写
   `"hotkey": "windows+j"`。
7. **钩子类软件的快捷键冲突无法自动检测**：只能检测通过 `RegisterHotKey` 注册的占用；
   保存后若按键无反应，换一个更复杂的组合即可。
